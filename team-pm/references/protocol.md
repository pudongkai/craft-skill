# 团队协作协议

`team-pm`、`team-product`、`team-dev`、`team-qa` 共用的规则：看板长什么样、任务单怎么流转、角色会话怎么领活、交活、提问。

看板脚本：`python3 ~/.claude/skills/team-pm/scripts/board.py <命令>`，下文简写为 `board`。

## 看板

根目录默认 `~/.claude/team/`，环境变量 `TEAM_BOARD` 可以改。

```
~/.claude/team/
  config.json                 # 并发上限、权限模式、通知方式
  events.jsonl                # 事件流，PM 靠它被叫醒
  projects/<项目名>/
    project.md                # 项目卡
    items/0001-product-prd.md # 任务单，编号在项目内递增
```

**状态在看板，内容在仓库。** 看板只记状态、结论和文档路径；需求文档、技术方案、测试计划、测试报告写在项目仓库里，提交到项目分支。

## 项目卡

`board project show <项目>` 查看。字段：

| 字段 | 含义 |
| --- | --- |
| 仓库 | 项目所在的 git 仓库 |
| 工作目录 | 本项目专用的 worktree，所有角色会话都在这里干活 |
| 分支 | 本项目的分支，默认 `feat/<项目名>` |
| 阶段 | `立项 需求 方案 开发 测试 验收 交付 完成 暂停`，只由 PM 改 |
| 人工确认 | 哪些确认点要人确认，默认 `需求, 方案, 交付` |
| 优先级 | `P0`～`P3`，派单时按它排序 |
| 基线 | 第一次派单建 worktree 时的提交 |
| 开发基线 | PM 进入开发阶段时记下的提交，开发的代码审查从这里算起 |

正文的“文档”一节登记需求、方案、测试计划等文档的路径（`board project doc <项目> <种类> <路径>`）；“待人确认”一节是 PM 攒着要问人的问题；“记录”一节是阶段变化。

## 任务单

```
# 0002 开发：写技术方案
角色: 开发          # PM 产品 开发 QA 人
类型: 方案          # 需求 方案 测试计划 开发 测试 修复 验收 答疑 确认 其他
状态: 待领取
依赖: 0001
会话:
重试: 0
输入: docs/prd/order-refund.md
产出:
来源:               # 由哪张单引出，如答疑单、修复单写发现问题的单号
派出时间:           # dispatch 时写入

## 说明
要做什么、完成标准

## 结果
完成时写三五行结论
```

**状态流转：**

```
待领取 ──dispatch──▶ 进行中 ──done──▶ 完成
                       │
                       ├──block──────▶ 阻塞      （等别的角色答疑）
                       └──ask-human──▶ 待人确认  （等人决定）
阻塞 / 待人确认 ──reply──▶ 待领取 ──dispatch──▶ 新会话接着做
PM 可以把任何单改成 取消。
```

- `dispatch` 派出会话时就把单改成进行中；会话里的 `item claim … --resume` 只是确认这张单还能做。
- 答复统一由 PM 用 `board item reply <项目> <编号> --text "<答复>"` 记进任务单的“答复”一节，单子随即回到待领取；PM 再次派出时开一个新会话，凭任务单的“结果”“答复”两节和工作目录里的改动接着做。

- “结果”一节是给 PM 看的：PM 不读产出全文，只读这一节决定下一步。写结论、产出路径、遗留问题，不写过程。
- 阻塞、待人确认时，“结果”一节写清楚在等什么、已经做到哪，重派后的会话凭它接着做。

## 角色会话怎么干活

每个角色由 PM 派出，只处理一张任务单，做完就结束。默认以子 agent 方式运行（`agents/` 下的同名 agent 定义，预加载角色 skill），也可以配置成独立的后台会话；下文的“角色会话”两种都指。派单提示里会给出项目名、任务单编号和工作目录。角色需要时可以再派自己的子 agent，交代清楚工作目录和范围。

1. **领取**：按派单提示运行 `board item claim <项目> <编号> --resume`。读项目卡和任务单，读“输入”里的文档。
2. **干活**：按本角色 skill 做。只改本单范围内的文件。工作目录是项目专用的 worktree，不要切分支、不要动别的 worktree。
3. **遇到问题**：
   - 能从代码、文档里查清的，自己查。
   - 有合理默认做法的，自己决定，写进产出文档和“结果”。
   - 需要别的角色回答的：建一张答疑单（`board item new <项目> --role 产品 --type 答疑 --from <本单编号> --desc "<问题，附你建议的答案>"`），然后 `board item block <项目> <编号> --reason "等 <答疑单号> 答复：<问题>"`，结束。答疑单完成后 PM 会把答案 `reply` 到你的单上再派回来。
   - 必须由人决定的（方向性取舍、要花钱、不可逆操作、需要凭据）：`board item ask-human <项目> <编号> --question "<问题，附选项和你的建议>"`，结束。
   - **不在会话里直接问人。** 后台会话没人看着，问了也没人答。
4. **提交**：产出的文档、代码提交到项目分支。只提交自己改的文件：`git add <路径>` 后用 `git commit -m "…" -- <路径>`（同一个工作目录里可能有别的角色在并行提交，不带路径会把别人暂存的文件一起提交；不要 `git add -A`），不提交 `.claude/` 下的文件。不推送。
5. **交活**：`board item done <项目> <编号> --output "<产出路径或提交号>" --result "<三五行结论>"`，然后结束。

角色会话的 Stop hook（子 agent 方式写在 agent 定义里，session 方式由派单时注册）会在任务单还是“进行中”时拦住停止，提示先 `done`、`block` 或 `ask-human`。

## 角色之间的分工

| 角色 | 负责的任务单类型 | 产出 |
| --- | --- | --- |
| 产品 | 需求、答疑（需求类）、验收、方案覆盖检查（类型写“其他”） | `docs/prd/<项目>.md`、验收结论 |
| 开发 | 方案、开发、修复、答疑（技术类） | 技术方案、代码、本地提交 |
| QA | 测试计划、测试（含回归）、答疑（测试类） | `docs/test/<项目>.md`（测试计划）、`docs/test/<项目>-report.md`（测试报告）、修复单 |
| PM | 立项、派单、汇总、交付 | 项目卡、给人的汇报 |
| 人 | 确认 | 由 PM 代为记录 |

## 文档位置

| 文档 | 路径 | 谁写 | 登记到项目卡 |
| --- | --- | --- | --- |
| 需求文档 | `docs/prd/<项目>.md` | 产品 | `project doc <项目> 需求 <路径>` |
| 技术方案 | 沿用仓库已有方案目录，没有时 `docs/design/<日期>-<项目>.md` | 开发 | `project doc <项目> 方案 <路径>` |
| 测试计划 | `docs/test/<项目>.md` | QA | `project doc <项目> 测试计划 <路径>` |
| 测试报告 | `docs/test/<项目>-report.md` | QA | `project doc <项目> 测试报告 <路径>` |
| 验收结论 | `docs/test/<项目>-acceptance.md` | 产品 | `project doc <项目> 验收 <路径>` |

修复单由 QA（测试发现）或产品（验收发现）建，指给开发，`--from` 写发现问题的那张单。修复单全部完成后，PM 建回归测试单给 QA（标题写“回归”，`--from` 列出全部修复单号，逗号分开）；验收发现的问题修复并回归后，PM 再建验收单给产品。

找某张单引出的单：`board item list <项目> --from <单号> [--type 修复]`。

## 并发规则

- 每个项目一个 worktree、一个分支，不同项目互不影响。
- 同一项目同一时间最多一张代码类单（开发、修复）在跑；文档类单可以同时跑，但只提交自己的文件。
- 全局、单项目同时运行的会话数受 `config.json` 的 `max_sessions`、`max_sessions_per_project` 限制，`board ready` 已经扣掉，PM 照着派即可。

## 事件

`events.jsonl` 每行一条：`序号`、`时间`、`项目`、`任务单`、`事件`、`说明`。`事件` 取值：

| 事件 | 谁写 | 含义 |
| --- | --- | --- |
| 完成 | `item done` | 单做完了 |
| 阻塞 | `item block` | 等别的角色 |
| 待人确认 | `item ask-human` | 等人决定 |
| 会话停下 | 角色会话的 hook | 会话停了但单没收尾，或卡在授权提示上 |
| 会话退出 | `board reap` | 单还在进行中，会话已经不在了 |

`board events --since <序号>` 打印某个序号之后的事件。
