# Claude 接力

把当前任务交给另一台 Mac 上的 Claude。两台 Mac 互相都可以接力。

脚本（相对本技能目录，运行前拼成绝对路径）：

- `scripts/peer.py`：找到对方机器并在上面执行操作，命令见文件开头的说明。`<机器>` 写电脑名的一部分即可，如 `m16`。
- `scripts/register.sh`：把本机地址登记到 iCloud 云盘，由 launchd 自动运行。
- `scripts/install.sh`：安装登记任务；`install.sh uninstall` 卸载。

## 怎么找到对方

每台 Mac 上有一个 launchd 任务，登录时、网络变化时和每隔 5 分钟，把本机的电脑名、主机名、用户名、IP 写进 `iCloud 云盘/ClaudeHandoff/hosts/<主机名>.json`。两台 Mac 登录同一个 Apple 账户，所以都能读到对方的登记。

`peer.py` 按登记的地址连过去，连上后核对主机名，对不上就不算连通。SSH 主机密钥按主机名记录，地址变了也能认出是不是同一台机器。登记很久没更新时，对方可能在睡眠、关机或换了网络，`peer.py` 会在报错里说明。

## 首次设置（每台 Mac 一次）

`peer.py list` 能列出对方、`peer.py resolve <机器>` 能连通，说明设置完成，跳过本节。否则逐项检查，需要用户在对方机器上手动做的，把命令整理好交给用户：

1. **装好技能**：craft-skill 拉到最新，`~/.claude/skills/claude-handoff` 指向仓库里的 `claude-handoff`。
2. **登记地址**：运行 `scripts/install.sh`。iCloud 云盘要开着。
3. **远程登录**：系统设置 → 通用 → 共享 → 打开“远程登录”。
4. **互相加公钥**：把本机 `~/.ssh/id_ed25519.pub`（或其他公钥）加到对方的 `~/.ssh/authorized_keys`，权限 `~/.ssh` 700、`authorized_keys` 600。双向接力时两边都要加。
5. **允许远程控制“终端”**：接力时通过 SSH 让对方的“终端”应用弹出窗口。第一次接力时对方屏幕上会弹出授权提示，要点“允许”；没点到或点了拒绝，`launch` 会报错，到对方的 系统设置 → 隐私与安全性 → 自动化 里允许 sshd-keygen-wrapper 控制“终端”。
6. **对方的 Claude Code 版本**：窗口里启动的 Claude 用的是对方终端里的 `claude`。启动后屏幕第一行会显示版本号，和本机差得太多时提醒用户，phased-dev-loop / dev-flow 的 Stop hook 在旧版本上可能不生效。

## 接力流程

### 1. 确认对方在线

`peer.py resolve <机器>`。连不上就把报错原因告诉用户，停下。

### 2. 写交接文档

在项目里写 `.claude/handoff-<YYYYMMDD>-<任务简称>.md`，让对方的 Claude 不看这段对话也能接着做：

- **目标**：要完成什么，做到什么程度算完成。
- **当前进度**：已经做完的、正在做的、还没做的。用 phased-dev-loop / dev-flow 开发时，进度以技术方案为准，这里写方案路径和当前环节，不重复列阶段。
- **关键信息**：涉及的文件、做过的决定和原因、用户提过的要求、试过但不行的做法。
- **怎么验证**：要跑的测试、构建命令或检查项。
- **要用的技能**：接着做需要用到的技能名，以及每个技能用来做哪一步（如“用 dev-flow 技能推进，当前环节：代码审查”）。不需要技能就写“无”。
- **分支和提交**：分支名、最后一个提交号。

只写结论，不贴大段日志和对话。

### 3. 提交并推送分支

- 只提交本任务的改动，不提交 `.claude/` 下的本地状态文件（交接文档另外复制，不走 git）。
- 推送是对外操作，先告诉用户要推送哪个分支、包含哪些提交，用户同意后再推送。
- 工作区里和本任务无关的改动不提交，也不要 stash 或丢弃，在交接文档里写明。

### 4. 在对方准备代码

1. `peer.py find-project <机器> <origin 地址>` 找到对方的仓库目录。找到多个时选和本机目录名相同的；找不到就问用户要不要克隆、放在哪。
2. `peer.py ssh <机器> 'cd <目录> && git status --short'`。对方有未提交的改动时**停下问用户**，不要覆盖、stash 或丢弃。
3. `peer.py ssh <机器> 'cd <目录> && git fetch && git checkout <分支> && git pull --ff-only'`。

### 5. 复制交接文档

`peer.py copy <机器> <本地交接文档> <对方目录>/.claude`，必要时先 `peer.py ssh <机器> 'mkdir -p <对方目录>/.claude'`。脚本会核对两边内容一致，输出“两边内容一致”才算复制成功。

### 6. 在对方启动 Claude

`peer.py launch <机器> <对方目录> <会话名> "<提示词>"`

- 默认在对方弹出一个“终端”窗口运行 Claude。窗口在对方的图形界面里，能读到钥匙串里的登录信息，用户在对方屏幕上直接就能看、能操作。
- 输出里的“窗口编号”（`/dev/ttys…`）记下来，之后查看对方屏幕要用。Claude 会改写窗口标题，所以不按标题找窗口。
- 会话名用 `handoff-<任务简称>`，只作为窗口刚打开时的标题。
- 对方不方便弹窗口（比如没人在用、锁屏）时，加 `--tmux` 改为在对方的 tmux 里启动，这时编号就是会话名。tmux 方式要求对方本地终端里已经有 tmux 在运行（`tmux new -d -s main`），否则读不到登录信息。
- 提示词：`读 .claude/handoff-<…>.md，按里面的说明接着完成任务。任务全部完成后删除这份交接文档。`
- **需要对方使用技能时，在提示词里写明技能名**，不要只靠对方从任务描述里自己判断该用哪个。写成“使用 <技能名> 技能<做什么>”，放在提示词开头，例如：
  - `使用 dev-flow 技能，按流程开发 docs/design/2026-11-03-order-refund.md。先读 .claude/handoff-<…>.md 了解当前进度。…`
  - `使用 phased-dev-loop 技能，按技术方案 <方案路径> 把剩下的阶段做完。…`
  - 用到多个技能时逐个写明，并说明各自用在哪一步。
- 启动前确认对方装了这些技能：`peer.py ssh <机器> 'ls -d ~/.claude/skills/<技能名> <对方目录>/.claude/skills/<技能名> 2>/dev/null'`。没有就停下告诉用户，同一个技能两边版本不一致时（如对方的 craft-skill 没拉到最新）也先告诉用户，用户同意后再在对方拉取更新。
- 脚本启动后等 15 秒，打印对方屏幕的最后几行。看到没登录、询问是否信任目录等提示时，按提示告诉用户怎么处理。

### 7. 清理本机的交接文档

第 5 步确认复制成功、第 6 步 Claude 已经在对方正常启动（屏幕上没有未登录、没有等待确认信任目录）后，删除本机的交接文档，以对方那份为准。任一步没成功就保留，用户可能要在本机接着做。

对方那份由接手的 Claude 在任务全部完成后删除（见第 6 步的提示词）。不在读完后立刻删，因为对方的对话被压缩后还要重新读它。

### 8. 告诉用户

- 交给了哪台机器、哪个目录、哪个分支；本机的交接文档是否已删除。
- 在对方机器上查看进度：直接看弹出的终端窗口；用 `--tmux` 启动的，执行 `tmux attach -t <会话名>`（看完按 `Ctrl-b d` 退出，不会打断它）。
- 本机这边之后不要再改同一个分支，避免两边冲突。

用户之后问进度时，用 `peer.py screen <机器> <窗口编号>` 看对方屏幕的最后 40 行。

## 注意

- 两台 Mac 要在能互相连通的网络里。公司网络如果屏蔽了设备之间的连接，登记了地址也连不上。
- 不在对方机器上做设置以外的改动：不删文件、不改配置、不处理对方未提交的改动。
- 卸载：每台 Mac 上运行 `scripts/install.sh uninstall`。
