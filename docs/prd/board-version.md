# board.py version 子命令需求文档

项目: board-version
作者: 产品（团队角色）　　日期: 2026-11-24
状态: 草稿

## 1. 背景与目标

团队看板脚本 `team-pm/scripts/board.py` 目前没有办法查看自己的版本，也没有直接显示看板数据放在哪个目录（看板根目录默认是 `~/.claude/team`，可用环境变量 `TEAM_BOARD` 改）。排查问题时，使用者要翻代码或环境变量才能确认“跑的是哪个版本的脚本、读写的是哪个看板目录”。

目标：运行 `board.py version` 即可在终端看到脚本版本号和当前生效的看板根目录绝对路径。

## 2. 用户与场景

| 用户 | 场景 | 现在怎么做 / 痛点 |
| --- | --- | --- |
| PM 会话 / 使用看板的人 | 排查看板问题、确认装的是哪个版本的脚本 | 只能看代码，没有版本号 |
| PM 会话 / 使用看板的人 | 设置了 `TEAM_BOARD` 或在多个看板之间切换，想确认当前读写的是哪个目录 | 要自己去看环境变量和代码里的默认值 |

## 3. 功能需求

### 3.1 用户故事

- US-1：作为看板使用者，我想要运行 `board.py version` 看到脚本版本号，以便确认当前用的是哪个版本。
- US-2：作为看板使用者，我想要同时看到当前生效的看板根目录，以便确认数据读写的位置。

### 3.2 业务规则

- BR-1：版本号定义在 `board.py`（或其导入的看板模块）中的一个模块级常量里，`version` 子命令打印的就是这个常量的值；改版本只需改这一处。本次版本号定为 `0.1.0`。
- BR-2：版本号格式为 `主.次.修订` 三段数字（语义化版本）。
- BR-3：看板根目录与看板其他命令实际使用的目录一致：设置了非空的 `TEAM_BOARD` 时用它，否则用 `~/.claude/team`；打印时展开 `~`，输出绝对路径。
- BR-4：输出固定两行，格式如下（`<…>` 处为实际值）：
  ```
  版本: 0.1.0
  看板根目录: /Users/xxx/.claude/team
  ```
- BR-5：`version` 只读：不创建看板根目录及其中任何文件，不写事件；看板根目录不存在时照常打印路径，退出码为 0。
- BR-6：`version` 不接受位置参数；多给参数时按 argparse 默认行为报错，退出码非 0。

## 4. 验收标准

| 编号 | 前置条件 | 操作 | 期望结果 | 对应 |
| --- | --- | --- | --- | --- |
| AC-1 | 未设置 `TEAM_BOARD` | 运行 `python3 team-pm/scripts/board.py version` | 退出码 0；标准输出恰好两行：第一行 `版本: 0.1.0`，第二行 `看板根目录: <家目录>/.claude/team`（`<家目录>` 为 `$HOME` 的值，不含 `~`） | US-1、US-2、BR-3、BR-4 |
| AC-2 | `TEAM_BOARD=/tmp/xx-board`（目录可以不存在） | 运行 `TEAM_BOARD=/tmp/xx-board python3 team-pm/scripts/board.py version` | 退出码 0；第二行为 `看板根目录: /tmp/xx-board` | US-2、BR-3 |
| AC-3 | `TEAM_BOARD='~/my-board'` | 运行 `version` | 第二行为 `看板根目录: <家目录>/my-board`，不含 `~` | BR-3 |
| AC-4 | `TEAM_BOARD` 指向一个不存在的目录 | 运行 `version` | 退出码 0；运行后该目录仍不存在 | BR-5 |
| AC-5 | 已有一个看板根目录，记下 `events.jsonl` 的内容（不存在则记为不存在） | 运行 `version` | 运行前后看板根目录下的文件列表和 `events.jsonl` 内容不变 | BR-5 |
| AC-6 | 无 | 把 `board.py` 里的版本常量临时改成 `0.2.0` 后运行 `version` | 第一行为 `版本: 0.2.0`；代码里搜索 `0.1.0`，除该常量外没有别处硬编码版本号 | BR-1 |
| AC-7 | 无 | 运行 `board.py --help` | 子命令列表里出现 `version`，带一句中文说明 | US-1 |
| AC-8 | 无 | 运行 `board.py version extra` | 退出码非 0，标准错误有 argparse 的用法报错 | BR-6 |
| AC-9 | 无 | 运行看板现有自动化测试（如有） | 全部通过，原有子命令行为不变 | — |

## 5. 本次不做

- 不加 `board.py --version` / `-V` 全局参数，只做 `version` 子命令。
- 不做 JSON 等机器可读的输出格式。
- 不打印 Python 版本、git 提交号、配置文件内容等其他信息。
- 不做版本检查、升级提示、看板数据格式的版本迁移。
- 不给 team-dev / team-product / team-qa 等其他脚本加版本号。

## 6. 已做的假设

- 输出格式用 BR-4 的两行“标签: 值”中文格式：和看板其他命令的中文输出风格一致，人和脚本（按行取冒号后内容）都好读。
- 看板根目录不存在时不报错、也不创建：`version` 是诊断用的只读命令，不应有副作用。
- 版本常量可以放在 `board.py` 或 `board_store.py`，由开发定；需求只要求“一处定义、`version` 打印它”。
- `team-pm/` 已在提交 7727268 纳入仓库，项目基线即该提交，开发直接在本分支修改 `team-pm/scripts/board.py`。
