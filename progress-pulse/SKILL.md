# 定时自我汇报

目标：解决“任务一旦起了头，中间很久没声音，主管要追问才知道到哪了”这个问题。本技能本身不负责干活，
也不负责定时唤醒——定时靠 `jobs` 技能登记的自动任务，这个技能只定义“被唤醒后查什么、怎么判断有没有
新进展、简报怎么写”。

## 登记一次定时汇报

主管说“定时汇报”“每隔 X 小时跟我同步一下”“盯着的事阶段性汇报”时：

1. 问清楚两件事（主管已经说清的不用再问）：多久一次（或在哪些时间点）、发给谁（默认发回当前会话）。
2. 用 `jobs` 技能的标记登记一个自动任务，`prompt` 固定写：
   ```
   按 progress-pulse 技能自检：逐项检查正在跟进的事，把有新进展/新卡点的整理成简报；
   全部和上次一样就首行写 NO-REPORT。
   ```
   例：
   ```
   [[定时任务: {"action":"add","title":"进展汇报","cron":"0 10,15 * * 1-5","prompt":"按 progress-pulse 技能自检：逐项检查正在跟进的事，把有新进展/新卡点的整理成简报；全部和上次一样就首行写 NO-REPORT。","deliver":"here"}]]
   ```
3. 登记后把系统返回的确认原样回给主管（`jobs` 技能的规矩）。

## 到点运行时查什么

按下面顺序检查，**只检查装了对应技能、确有其事的部分**，没装的跳过，不要编：

1. **被盯梢的会话**（装了 `watch-task` 技能时）：跑它的 `list` 看现在在盯什么，再跑 `check` 看有没有新状态。
2. **分阶段开发中的技术方案**（装了 `phased-dev-loop` 技能、且知道项目路径时）：读项目 `.claude/dev-loop/ACTIVE`
   指向的方案，看开发状态和阶段标记比上次汇报时有没有变化（新增 `[x]`、变成 `BLOCKED`、全部完成）。
3. **交办/提交出去还没收尾的事**：凭对话上下文和记忆里记的“等谁回复”“等审批结果”这类条目，看有没有新结果；
   问不到就如实说“还没有新回复”，不要编进展。
4. 以上都没有变化 → 这一轮没有可汇报的内容。

## 简报怎么写

- 每件有新进展的事一行：**事项 — 现在到哪一步/什么状态 — 有没有卡点或需要主管做什么**。
- 只写比上次汇报时**有变化**的部分，一直没变化的事项不要每次都重复列出来陪跑。
- 全部没变化 → 按 `jobs` 的规矩，首行写 `NO-REPORT`，不发消息打扰。
- 遇到卡住、出错、需要主管决策的 → 不等定时点，当场按各自技能（如 `watch-task`）的规则立刻播报；
  定时汇报只补“按时同步”这一层，不是唯一的播报渠道。

## 纪律

- 这是个“收集状态 + 组织播报”的壳，不替代具体任务怎么做；干活、判断卡没卡，按各自的技能或常规流程来。
- 定时任务本身的设置/改时间/暂停/删除，一律按 `jobs` 技能的规矩来（只有主管能设置）。
- 没有新进展就不要为了“显得在干活”硬凑内容，那样之后主管会把消息当噪音划走。
