# 技术方案里开发计划的写法

phased-dev-loop 直接在技术方案文档里标记进度，不另建进度文件。Stop hook 按下面的格式读取文档，写技术方案时按这个格式写开发计划，开发时就不用再转换。

## 必需的两样东西

**1. 开发状态行**（文档任意位置，一般放在标题下面）

```markdown
开发状态: RUNNING
```

中英文冒号、加粗（`**开发状态：** RUNNING`）都可以。取值：

| 值 | 含义 | hook 行为 |
| --- | --- | --- |
| `TODO` 或不写 | 方案还没开始开发 | 放行 |
| `RUNNING` | 正在按 loop 开发 | 有未完成阶段时拦截停止 |
| `BLOCKED` | 需要用户做决定 | 放行 |
| `DONE` | 全部完成并通过最终验证 | 放行 |

**2. 开发计划章节**：标题里包含“开发计划 / 实施计划 / 开发阶段 / 阶段划分 / 实施步骤”之一。hook 只统计这个章节里的阶段，其他章节（验收标准、风险等）里的复选框不会被当成阶段。

## 阶段标记

阶段写成顶层列表项（行首就是 `- [ ]`，不缩进），阶段的详情写成缩进两格的子项。不要写成 `### [ ] 阶段1` 这样的标题，标题里的复选框在 Markdown 里渲染不出来。

| 标记 | 含义 |
| --- | --- |
| `[ ]` | 未开始 |
| `[~]` | 进行中（同一时间只有一个） |
| `[x]` | 已完成（下面必须有验证记录） |
| `[!]` | 卡住（下面写清原因） |

hook 只统计顶层列表项，缩进的子项（包括子项里的复选框）都不算阶段。

Markdown 只把 `[ ]` 和 `[x]` 渲染成复选框，`[~]` 和 `[!]` 会显示成普通文字，这不影响 hook 读取。

## 示例

```markdown
# 订单退款技术方案

开发状态: RUNNING

## 背景
...

## 开发计划

- [x] 阶段1：退款数据模型
  - 涉及模块：order-service
  - 完成标准：迁移脚本可执行；`RefundRepository` 单测通过
  - 验证：`mvn -pl order-service test` 通过（42 个用例）；改动 `Refund.java`、`V12__refund.sql`

- [~] 阶段2：退款接口
  - 涉及模块：order-service、payment-gateway
  - 完成标准：`POST /refunds` 集成测试通过

- [ ] 阶段3：管理后台页面
  - 涉及模块：admin-web
  - 完成标准：`pnpm test` 和 `pnpm build` 通过
```
